# 文件夹图标（Morz 插件）

给 Morz 文件树的文件夹设置 Lucide 图标：在文件树右键设置，图标可搜索（支持中文），
2102 个图标全部内置于插件内部，不联网。

版本 1.0.0 ｜ SDK v1.8 ｜ `main.js` 373 KB

---

## 安装

**已安装到本机**：`%APPDATA%\com.morz.editor\plugins\folder-icons\`

首次使用需两步：

1. 设置 → 第三方插件 → 打开插件系统开关（若尚未开启）
2. 在列表里启用「文件夹图标」

卸载：删除上述目录即可。

其他机器安装：Morz 设置 → 第三方插件 → 「从本地文件夹安装」→ 选择本目录
（只需 `manifest.json` + `main.js` 两个文件）。

---

## 用法

**主路径**：文件树里右键任意文件夹 → 插件 → **设置文件夹图标…** → 光标处弹出小浮层 → 搜索并点选图标，
文件树立刻更新，**浮层保持打开**，可顺手调颜色/角标，点浮层外部或 × 关闭。不打断当前文档。

| 入口 | 位置 | 形态 |
|---|---|---|
| 设置单个文件夹图标 | 文件树右键 → 插件 → 设置文件夹图标… | 光标处浮层 |
| 清除单个文件夹图标 | 文件树右键 → 插件 → 清除文件夹图标 | 直接执行 |
| 为当前文档所在文件夹设置 | 命令面板 → `文件夹图标：为当前文档所在文件夹设置` | 浮层（窗口居中） |
| 总览 / 名称规则 / 数据 | 文件树右键 → 插件 → 文件夹图标总览；或点状态栏「N 个文件夹已设图标」；或浮层底部「完整面板」 | 主区域视图 |
| 一键清空 | 命令面板 → `文件夹图标：清除全部自定义图标` | 直接执行 |

浮层只做「挑一个图标」这一件事；名称规则那种需要横向空间的编辑留在主区域视图里。

**搜索**支持英文名（`cal` → calendar）、中文关键词（`日历` / `会议` / `项目` → 对应图标）、
以及全名子串。前缀命中优先，短名优先。

## 设置项（设置 → 插件 → 文件夹图标）

| 项 | 说明 |
|---|---|
| 在文件树显示自定义图标 | 总开关 |
| 文件夹默认图标 | 未单独设置的文件夹统一用它；留空则不装饰（保持原样）。例：`folder-open` |
| 图标颜色 | CSS 颜色或主题变量，如 `var(--primary-color)`；留空跟随主题前景色 |
| 统一角标 | 最多 3 字符，显示在图标旁 |
| 悬停显示文件夹名 | 默认开 |
| 启用名称规则 | 默认开 |

**优先级**：单文件夹图标 ＞ 名称规则（自上而下首个命中）＞ 全局默认图标。

名称规则（视图内「名称规则」页）：支持 `包含` / `开头是` / `正则` 三种匹配，可排序。
例：`包含 会议 → calendar`，`正则 ^\d{4}-\d{2}$ → calendar-days`。

## 图标和文件夹怎么对上（存储模型）

配置是一张**以文件夹路径为键的扁平表**，不存在"当前目录"概念，所以切换目录、折叠展开、
换标签页都不会丢状态：

```json
{
  "v": 2,
  "folders": {
    "notes/项目": { "icon": "rocket", "color": "#60a5fa", "badge": "P" },
    "notes/周报": { "icon": "inbox" }
  },
  "rules": [{ "id": "r1", "type": "contains", "p": "会议", "icon": "calendar" }]
}
```

存在 `ctx.storage` 的 `config` 键下，`activate` 时**一次性读入内存**；`decorate` 每行只做一次
查表（O(1)、同步），符合宿主的硬约束。

**它到底在哪个文件里？** 宿主没有公开 `ctx.storage` 的落盘路径，文档只承诺三件事：按插件 id 隔离、
卸载插件一并删除、value 走结构化克隆。所以不要去找某个能手改的 `data.json`——
想看得见，就打开视图的**「数据」页**：里面就是这份 JSON 原文，可复制备份、也可粘贴回来覆盖。

首次写入发生在你点选第一个图标的那一刻。在此之前插件目录里只有 `manifest.json` / `main.js` / 图标，
没有任何数据文件。

| 层 | 存什么 | 什么时候算 | 切换目录时 |
|---|---|---|---|
| 单文件夹 | `folders["路径"]` | 用户点选后立即写盘 | 按路径精确命中 |
| 名称规则 | `rules[]`，不存匹配结果 | 每次装饰时按文件夹名现算 | 命中与否随名字走 |
| 全局默认 | settings 里的标量 | 前两层都没命中时兜底 | 全库一致 |

**路径口径统一在 `normPath()`**：反斜杠转正斜杠、折叠重复斜杠、去首尾斜杠。
装载时把旧数据里不规范的 key 归一后回写一次，之后每次查表只比字符串。
大小写用 `idxLower`（小写路径→真实 key）兜底，Windows 上只改大小写的改名也能命中。

浮层顶部有一行**来源提示**（蓝点=手动、黄点=规则、绿点=默认），说明当前图标是哪一层给的，
避免"我明明没设过，它怎么有图标"。

**目录改名/移动**：`vault.on("rename")` 先按目录前缀整体迁移，再攒 450ms 校验旧目录是否还有文件，
确认是目录级移动才落盘；只移动单个文件不会动文件夹图标。
**目录被删**：配置项会留成孤儿，总览页会异步用 `vault.exists()` 核对，标灰并给一个手动「清理」按钮，
不自动删。

## 图标资源

| 文件 | 用途 |
|---|---|
| `icon.svg` | 24×24 线性图标（`currentColor`），与 Lucide 同规格：文件夹 + 内嵌 sparkle |
| `icon-128.svg` | 128×128 商店图标源文件（圆角蓝底 + 白色文件夹 + 琥珀 sparkle） |
| `icon-128.png` | 128×128 成品，用于插件索引的 `icon` 字段（市场按 24px 显示） |

取色：底 `#4c6ef5 → #1e3a8a`（150° 渐变），文件夹 `#ffffff`，sparkle `#fbbf24`。
`manifest.json` 本身没有 icon 字段（官方字段表：`id/name/version/description/author/sdk/main/permissions`），
商店图标走索引条目的 `icon`；16–24px 下仍可辨识的是"文件夹 + 一点亮色"，所以没做细节纹理。

**设置里的「第三方插件」列表不显示这个图标，也显示不了。** 官方文档里插件列表只描述
Beta 徽章、性能停用徽章，没有任何图标位；manifest 也没有 `icon` 字段。`icon` 只存在于
**插件索引条目**（市场卡片按 24px 显示）。这是宿主的缺口，不是文件没放对——
`icon.svg` / `icon-128.png` 已经和 `main.js` 放在同一目录，随时可用。

插件**内部**的图标位（视图 tab、文件树右键菜单）只接受内置/Lucide 名，不能传自定义 SVG，
所以那里用的是同语义的 `folder-cog` / `folder-x` / `folder-tree`。

## 实现要点

- 走 SDK v1.8 的两个原生扩展点：`ctx.ui.decorateFileTree`（文件树装饰）与
  `ctx.ui.fileTreeMenu`（文件树右键，`when: "folder"`）
- 浮层是自建 DOM（`position: fixed`，挂 `document.body`），不覆盖全屏、不接管工作区；
  关闭走「点外部 mousedown / Esc / ×」三条路径，没有透明遮罩
- `fileTreeMenu` 的 `run(ctx)` 只给 `{workspaceId, path, name, kind}`，**没有光标坐标**；
  插件自己监听 `contextmenu` 捕获阶段记下 `clientX/clientY`，用于浮层定位
- `decorate` 必须同步且 O(1)：配置在 `activate` 时一次性读入内存，逐行只做一次对象查表
- 图标以**内联 SVG 片段**（`<path>` 开头）传给宿主，不依赖宿主内置 Lucide 版本
- 文件夹改名 / 移动：监听 `ctx.vault.on("rename")`，攒 450ms 后校验旧目录下是否还有文件，
  确认是目录级移动才迁移配置，避免"移走一个文件"误改文件夹图标
- 权限：`vault:read` `workspace` `views` `settings`。不写库、不联网、不碰正文

## 开发

```
folder-icons/
├── manifest.json
├── main.js              # 构建产物（安装只需这个 + manifest）
├── build.js             # 合并图标数据与业务代码
├── preview.html         # 浏览器交互预览（加载真实 main.js）
├── src/
│   ├── app.js           # 业务代码
│   ├── lucide-icons.json  # 2102 图标，紧凑格式，337 KB
│   └── zh-aliases.json    # 90 组中文检索词
├── icon.svg            # 24px 线性图标
├── icon-128.svg/.png   # 商店图标（128×128）
├── test.js              # mock host 测试（18 项）
└── test-ui.js           # jsdom 浮层/视图测试（34 项）
```

```bash
node build.js     # 改完 src/ 必须重建
node test.js      # 核心链路
NODE_PATH=<jsdom 目录> node test-ui.js   # UI 交互
```

图标数据来源：`lucide-static@1.78.0` 的 `icon-nodes.json`，只保留 `d` 属性与形状节点，
去掉 `<svg>` 外壳与重复属性。升级图标集时重跑提取脚本即可。

> 注意：Lucide 1.78 移除了 `music` / `building-2` / `file-signature` / `filter` / `*-alert` 等旧名，
> 新增 `*-exclamation-point` 命名。改别名表前先校验名称是否存在。

## 已知限制

| 限制 | 说明 |
|---|---|
| 只有文件夹能设图标 | 宿主 `decorateFileTree` 对文件行同样生效，但本插件只处理 `kind === "directory"` |
| 空文件夹可以设图标 | 装饰对真实树行调用，所以空文件夹也在列 |
| 配置不随插件卸载保留 | 存于 `ctx.storage`，卸载即清。重要配置请截图或另外备份 |
| 多工作区共用一份配置 | `decorate` 的入口参数未提供 workspaceId，只能按路径存；两个工作区若有同名路径会共用一条配置（宿主缺口） |
| 全局默认图标会影响所有文件夹 | 想让多数文件夹保持原样时，请留空并改用名称规则 |
| 浮层位置依赖右键光标 | 从命令面板触发时没有光标，浮层居中显示在屏幕上半部 |
| 浮层是自建 DOM | 若宿主后续把文件树放进特殊层叠上下文，`position: fixed` 可能被遮挡；届时改挂 `ctx.ui.floatingHost` |
